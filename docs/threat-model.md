# Threat model

Assets: policy contents, conversations, memberships, identity sessions, storage objects, and provider budget. Actors: anonymous visitors, members, administrators, malicious uploaders, compromised model output, and operators.

Trust boundaries are browser to API, identity provider to session, API to database, worker to parser, and retrieved text to model. Every workspace route checks membership before setting RLS context. Sources are reauthorized when opened, including historical citations. Object keys are generated by the server. Model output is plain text, never HTML. Source references must be in the supplied evidence set and quotes must be exact substrings. These checks do not prove semantic entailment.

Uploads have byte, text, count, and type limits. Plain UTF-8 text and Markdown are supported in the initial local slice. PDFs must fail closed until a credential-free, network-disabled parser container is configured and tested. Malware scanning or content disarm is a prerequisite decision for external uploads. Local development storage is not a hosted storage solution.

Session abuse is limited through opaque sessions, expiry, secure production cookies, CSRF verification, and OIDC token validation. Tenant isolation is tested under a non-owner runtime database role. Usage reservations use locked database rows. Provider retries are disabled; each request has one bounded generation call and a deadline. The kill switch leaves administration available.

Residual risks: prompt injection, semantic misgrounding, denial of service, compromised dependencies, operator access, and sensitive excerpts in historical messages. No security certification or production guarantee is claimed. Hosted login, provider quality, backup recovery, and external uploads require deployment-specific validation.
